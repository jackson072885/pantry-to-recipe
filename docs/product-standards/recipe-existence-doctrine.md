# Pantry to Plate — Recipe Existence Doctrine

Pantry to Plate is not a recipe storage system. It is a dinner decision product.

A recipe does not deserve to exist merely because it is technically valid. It must deserve to be chosen, trusted, and recommended.

A recipe may exist in Pantry to Plate only if it passes every Recipe Existence Standard completely.

A recipe passes completely only when:
1. the meal itself is worth existing
2. the page presents it clearly enough to be trusted

A recipe is not complete unless it is both **cookable** and **recommendable**.

## Product rule
- **If it passes completely, keep it.**
- **If it can be made to pass completely and is worth the effort to get it there, repair it.**
- **If it cannot be made to pass completely, or is not worth the effort required, remove it.**

## Recipe Existence Standards

### 1. Dish Identity Standard
The recipe must clearly communicate what the dish is and feel like a real, coherent dinner.

It does not pass if the dish feels random, misleading, generic, confused, or weaker than its title suggests.

### 2. Ingredient Logic Standard
The ingredients must honestly and logically support the claimed dish.

It does not pass if required ingredients are incomplete, optional ingredients are secretly essential, or the ingredient structure does not truly support the dish being claimed.

### 3. Instruction Standard
The cooking steps must be complete, correctly ordered, and trustworthy without guesswork.

It does not pass if important actions are hidden, sequencing is broken, or the user must fill in major gaps.

### 4. Outcome Standard
The page must make clear what the finished dish should taste like, feel like, or look like when done right.

It does not pass if the end result is vague or the user would not know what success looks like.

### 5. Dinner Value Standard
The recipe must earn its place as a dinner option by delivering meaningful payoff, realistic usefulness, and recommendation-worthy appeal.

It does not pass if it feels bland, weak, low-payoff, unrealistic, or not worth choosing for dinner.

### 6. Confidence Standard
The recipe page must reduce uncertainty enough that a normal user can move from interest to action without feeling under-informed.

It does not pass if the page leaves the user hesitant, confused, or unconvinced.

### 7. Uniqueness Standard
The recipe must contribute distinct value to the dataset and not exist as a redundant variation of a stronger recipe already in the app.

It does not pass if it mainly duplicates something better.

## Straight-to-remove triggers
Remove a recipe immediately if:
- the dish identity is broken
- the ingredient logic is dishonest
- the instructions are too broken to trust
- the result would still be weak even when followed correctly
- the recipe mainly exists as filler
- the recipe adds little distinct value compared with stronger existing recipes

## Core principle
A recipe should not survive because it is fixable in theory.
It should survive only if it can be made fully worthy of the product.
